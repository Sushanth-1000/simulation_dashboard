## 1. What ASTRA is

ASTRA is a **runtime safety-governance architecture for AI-controlled cyber-physical
systems**. It sits at the actuation boundary — the point where a decision becomes physical
motion — and answers one question on every control tick:

> *This untrusted learned controller wants to move the vehicle. Should it be allowed, and
> what is the evidence for that answer?*

The central design commitment is that the learned controller is **assumed untrustworthy**.
It can drift, it can be adversarially perturbed, and it can be confidently wrong in states
it has never seen. Every structure downstream of it is designed against that threat model.

### The property that distinguishes ASTRA from prior art

Classical runtime assurance answers "out of certified envelope" with a **safe stop**. For a
mining hauler, a field robot, or a highway vehicle inside a tunnel, stopping is frequently
*itself* the hazard.

ASTRA's answer is a **narrowed envelope, not a halt**: when no certified profile matches
the situation, the Runtime Calibration Manager engages **bounded safe exploration** — half
the nearest certified speed, a ±15° steering cone, no lane changes, full braking authority
retained, and evidence logged throughout. The vehicle keeps moving.

## 2. The nine-layer pipeline — all layers built

Every tick runs the following sequence. All ten components exist, are wired, and are
exercised by tests.

```
   L1  acquire      shared sensor bus, per-modality staleness and health
    │
   L2  estimate     dual-rate UKF (fast 50 Hz / slow 1 Hz), kinematic bicycle model
    │
   L3  trust        conformal Trust Index, Mondrian class-conditional quantiles
    │
   L4  propose      Core-A — the UNTRUSTED learned policy (PPO, Lagrangian-constrained)
    │
    ╞══ SI-5 one-way channel ══════════════════════════════════════════════════
    │   Core-A can write a proposal. Core-A has no method to read a verdict.
    │
   L5  predict      physics-informed digital twin (PINN), one-step command prediction
    │
   L6  gate ①       STATISTICAL — inductive conformal prediction + MMD shift detection
   L7b gate ②       PHYSICAL    — lateral jerk, model divergence, actuation limits
   L7a gate ③       DETERMINISTIC — hard safety shield, analytic stopping envelope
    │
    ├─ merge        fail-closed: an EMPTY verdict set is a VETO
    │
   L8  arbitrate    fail-safe state machine, graduated NOMINAL→DEGRADED→LIMP→SAFE_STOP
    │
   L9  issue        Runtime Calibration Manager — the ONLY component that may actuate
    │
        record      decision record → non-blocking JSONL audit sink
```

## 5. Stage ledger — what has been done

### ✅ Phase 1 — Foundation

Contracts (actuation, assurance, governance, audit, sensing), ports, invariant catalogue,
configuration schema and loader, observability, composition root, CLI, tooling, CI, and a
green quality gate from day one.

**Key decisions locked here:** `NewType` SI units, frozen slotted dataclasses, injected
`Clock` (no `datetime.now()` anywhere), packed `SymmetricMatrix`, and fail-closed defaults.

### ✅ Phase 2 — Perception and estimation

L1 shared sensor bus, L2 dual-rate UKF, replay spine (`StateRecorder` + `ReplayHarness`),
byte-identical replay verified, latency measured.

**Two fail-open defects found and fixed:**

1. **NaN staleness budget silently disabled fault detection.** `budget < 0` is `False` for
   NaN and `staleness > nan` is `False`, so a 1000-second-old reading classified as
   HEALTHY. Fixed with `require_non_negative` at both entry points.
2. **Cross-layout measurement corrupted state.** A slow-state measurement applied to the
   fast filter has indices 0,1,2 that are perfectly valid there — nothing raised, and road
   friction was written into the state as position and speed, driving speed from 12.0 to
   1.099 m/s silently. Fixed with a layout check in `_step`.

### ✅ Phase 3 — The safety spine

L7a hard safety shield, L8 fail-safe FSM, one-way Core-A→Core-B channel, SI-3
unsuppressable-veto verification, FSM round-trip, latency inside budget.

### ✅ Phase 4 — Core-B completion

L5 PINN twin, L6 statistical gate, L7b physical gate, L3 conformal trust, L9 hot and cold
paths. **All three gates and all nine layers now exist.**

### ✅ Stage 1 — Integration

The tick loop that made ten components a system. `DecisionRecord` extended to a complete
evidence row. One command driven end to end through the full pipeline into the audit log.

**Defect found:** latency p99 measured at **12.3 ms against a 10 ms budget**. Root cause
was the MMD `discrepancy` — an O(n²) Gaussian kernel — being computed **twice per tick**
(6 million kernel evaluations across 400 ticks). Memoised. **[M]** p99 dropped to
**1.98 ms**.

### ✅ Stage 2 — Calibration

Calibration corpora generated from the trained twin, per-class empirical coverage verified,
four `CalibrationProfile`s seeded, loading wired.

**Instructive investigation:** coverage initially read 92.6% and was flagged "BELOW
TARGET". Rather than tuning the quantile, `conformal_quantile` was Monte-Carlo'd first —
and found **correct to within 0.15 pp**. The *measurement* was underpowered: a single split
has sd ≈ 1.5 pp. Changed to averaging over 200 random splits. The formula was never wrong.

### ✅ Gap-closing work

| Item | Outcome |
|---|---|
| Flaky concurrency test | Reproduced under 12-way load — it **hung** rather than failed (unbounded barriers). Added `RENDEZVOUS_TIMEOUT` and `JOIN_TIMEOUT` |
| SI-8 timing test | Written. First version asserted the wrong thing — it obstructed `json.dumps`, but serialisation is on the caller *deliberately*. Rewritten to obstruct disk I/O |
| SI-9 checksum | Now **verified**, not merely stored |
| `TrustAssessment` | "Uncalibrated" made explicit rather than encoded as a quantile of 0.0 |
| `validation_fraction` collision | Contract said "fraction held out"; knowledge base used `is_valid = validation >= 1.0`. Every correctly-certified profile was permanently inadmissible. Fields separated |

### ✅ Tunnel scenario

The headline behaviour: no admissible profile → exploration engages → **vehicle keeps
moving**. 8 tests. **[M]** 0 unissued ticks in 60.

### ✅ Stage 4 (adapted) — a real trained policy

Stable-Baselines3 PPO under PID-Lagrangian duals for constraints C1–C3, with the veto rate
structurally excluded from the reward (SI-6).

**Adapted, not as specified:** Stage 4 calls for training against CARLA. CARLA ships no
macOS build, so the plant is the same kinematic bicycle model the UKF assumes. What that
does and does not license is documented in `astra/layers/l4_proposer/learned.py`.

**Four defects found, each by measurement rather than review:**

1. **The dual update could only ratchet upward.** Driven against the floored excess with a
   target of zero — an error that can never go negative, so λ₁ climbed while the constraint
   was *already satisfied*. Driving it against `J_C` vs `d` (what `LagrangianDual`'s own
   docstring asks for) fixed it. **[M]** λ₁ now rises to 0.29 under violation and decays
   back to 0.00 once satisfied.
2. **The plant multiplied control effectiveness by `dt`**, making it 50× less responsive
   than the `B·π = a_lat` convention the twin and L7b assume.
3. **Default Gaussian exploration** spans the whole steer channel — at 140 m/s²/rad that is
   ±70 m/s² of sampled lateral acceleration, so every rollout left the road. Presented as
   "PPO cannot learn this task"; actually "PPO never samples the task."
4. **C1–C3 bound no lateral command rate, but L7b enforces one.** The first policy
   satisfied all three constraints at 0.10 m mean deviation and demanded 194 m/s³ against
   an 8 m/s³ limit. Closed with action-rate regularisation in the objective — which touches
   neither the constraint set nor `TrainingSignal`, because it reads only the policy's own
   consecutive outputs.

**A reported number was also retracted.** A 100% jerk-veto rate was measured and reported,
then found to be an artefact of an **open-loop harness** that published a fixed sensor
payload every tick — pinning `a_now` at zero, so every non-zero proposal read as a jerk
violation. `training/closed_loop.py` was written so the next scenario cannot repeat it.
**[M]** Closed-loop, the true figure is **1 tick in 400**.

**[M]** Final training result:

```
C1  mean |lane deviation|      0.0892 m       (budget 0.875)
C2  mean |long. acceleration|  1.2887 m/s^2   (budget 4.000)
C3  collision rate             0.0000         (budget 0.000)
constraints satisfied: yes
```

**[M]** Closed-loop through the real pipeline, 400 ticks:

| | Veto rate | Mean \|lane deviation\| | Jerk violations | Ticks issuing a command |
|---|:--:|:--:|:--:|:--:|
| Deterministic placeholder | 59.8% | 0.836 m | 0 | **400 / 400** |
| **Trained PPO policy** | **41.0%** | **0.383 m** | **1 / 400** | **400 / 400** |

The learned policy beats the placeholder on both control quality and veto rate — and the
architecture's central availability claim holds under both.

### ✅ SI-6 promoted to mechanical

Last review-only invariant closed.

### ✅ FB1 — the first feedback loop

The estimator now learns what the vehicle was actually commanded to do.

Previously the fast model asserted lateral acceleration was constant between measurements,
so the filter could only learn about a manoeuvre *after* the IMU reported it — and with a
degraded or absent IMU, never. The vehicle was being steered by a command the estimator did
not know had been sent. This is precisely the shared-state common-cause channel the
architecture calls out.

**The design decision that matters:** the command enters the **prediction**, never the
state. Writing it into `x` would make the estimate agree with the command by construction
and destroy the innovation the system uses to detect that the vehicle is *not* doing what
it was told — the filter would report perfect health exactly when the actuator had failed.

**Closing FB1 invalidated the calibration corpus.** This is the concrete reason FB1 must
come first. The corpus was generated by a filter with the loop open; FB1 changes the state
estimate, the estimate changes the non-conformity score, and the quantile table no longer
described the distribution the gate was scoring. **[M]** Measured effect on the placeholder
with a stale corpus: veto rate **59.8% → 99.8%** with **no change to the policy**.
`generate_calibration.py` now runs FB1 too. After regenerating: per-class coverage
**94.96%–95.06%** against a 95% target, and the veto rate returns to 59.8%.

### 6.2 The limitation that matters most

> **Everything ASTRA currently knows about itself, it learned from equations it also wrote.**

The digital twin, the calibration corpus, and the trained policy **all descend from the same
kinematic bicycle model**. The generator and the judge agree by construction.

The consequences are specific and must travel with every number in this document:

- It **can** demonstrate that the plumbing works, that a learned policy drives the pipeline,
  that the gates evaluate genuinely learned commands, that the Lagrangian wrapper moves the
  constraint costs it should, and that the architecture keeps a vehicle moving under a 41%
  veto rate.
- It **cannot** support a false-positive or false-negative rate, because nothing here is
  out-of-distribution in the sense the statistical gate is calibrated for. **No gate
  accuracy figure exists, and none can exist until this changes.**

This is not a defect in the implementation. It is a provenance fact, and it is the single
highest-leverage thing to fix.

## 12. Closing position

ASTRA is, at this date, a **complete nine-layer runtime governance architecture** with all
ten separation invariants machine-enforced, a real trained policy under Lagrangian
constraints, the first feedback loop closed, 2,513 passing tests at 97.97% coverage, and a
demonstrated behaviour — keeping a vehicle moving under an unrecognised context rather than
halting — that distinguishes it from its prior-art table.

It is also a system that has **never met data it did not generate itself**, has no security
posture, and is written in a language that cannot be deployed at the actuation boundary it
is designed to govern.

Both of those sentences are true simultaneously, and stating only the first would make this
document useless to anyone deciding what to do next.

**The two decisions that determine the next five years are neither of them coding tasks:**

1. **Get one real dataset.** CARLA on a Linux cloud instance converts every estimated
   number in this project into a measured one, and moves it from TRL 4 to TRL 5.
2. **Choose the beachhead deliberately.** The cross-domain analysis says industrial
   robotics and defense research, not automotive OEMs. Same architecture, same code,
   materially better odds.
